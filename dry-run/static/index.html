Environment checks: --

not_a_robot.environment checks browser-observable automation artifacts -- navigator.webdriver, Selenium's cdc_* globals, Playwright/Puppeteer markers, software-rendered WebGL. It's not part of the behavioral model above; these are fixed, illustrative scenarios (not generated per run) run through the real score_environment() function. The stealth-patched row is deliberately identical, signal-for-signal, to the clean-browser scenario -- a stealth-patched bot passes every check here by design. That's exactly the gap the behavioral model above exists to cover.

Live Selenium check: --

The table above scores a hardcoded example of what an unpatched/ stealth-patched Selenium session looks like, assuming real GPU passthrough. This one is not an example: clicking Run Tests also launches two real headless Chromium instances in this container via Selenium -- one unpatched, one with a real CDP stealth patch that overrides navigator.webdriver and strips the injected cdc_* properties -- reads their actual signals, and scores them with the same score_environment() call. Verified empirically while building this: the stealth patch genuinely defeats both of those checks (both read false after patching), but both live instances run in this container, which has no real GPU -- so WebGL falls back to software rendering and still gets caught. That's not a contradiction with the hardcoded scenario above, it's a limit of this demo: a stealth-patched instance with real GPU passthrough would show a real renderer string and pass this layer entirely -- exactly the class not_a_robot's behavioral scoring above exists to catch, not something this container can demonstrate directly. Runs concurrently with the behavioral batch above (see app.run(threaded=True) in dry-run/app.py), not after it, since browser startup time has nothing to do with the ML training time.

Request fingerprint: --

not_a_robot.request_fingerprint is a third, deterministic layer: header/User-Agent plausibility checks, separate from both the behavioral model and the environment checks above. It deliberately does not check header order or TLS fingerprints (JA3/JA4) -- see the main README's Deterministic automation checks section for why. The first row needs no simulation -- it's whatever HTTP client (your browser, curl, a script) actually just called this endpoint to run this test; the rest are fixed, illustrative inputs (a known scraper library, a default headless-Chrome UA, and a Chromium UA missing the headers real Chromium sends) so this layer's behavior is visible on more than one row.
